# 2026-07-22-1437-87bd24-passoff-file

## Summary

Ran a ten-agent adversarial review of the Microsoft 365 Copilot regulatory labeling prompt library (`public/prompts/`), then applied the fixes and extended the library. Each of the nine original categories was reviewed for regulatory correctness, standalone Copilot fitness, beginner usability, internal consistency, and safety; the same nine reviewer agents were then sent back to apply their surviving findings against a shared fix spec. The dominant defect was that every fenced prompt-text referenced sections the user never pastes (its output-handling frontmatter and save path), so pasting a prompt into Copilot produced fabricated frontmatter; that is now fixed library-wide by inlining a self-contained output contract into every fence. Real regulatory errors were corrected (disease-claim routing, DSHEA disclaimer misuse, the 2024 "healthy" rule and plain-water auto-qualify, dual-column RACC thresholds, rounding increments, allergen enumeration, citation whitelists), approval-leaking vocabulary was removed, and human-sign-off plus unverified-citation banners were pushed into the outputs themselves. Added three new categories (setup, reflection, copilot-skills) and a user guide, deleted 15 redundant stub notes, made the `.md` files the single source of truth for the generated manifests and Word export, and merged everything to `main` via PR #34.

## Key decisions

- The `.md` prompt files are the single source of truth. `scripts/sync-prompt-manifests.py` regenerates each `.manifest.json` from them, and the Word export is built from those manifests, so the two delivery surfaces cannot drift from the prompts. `make test` now runs `prompts-check` and fails on manifest drift.
- Bases keep v2's bracket notation for hyphenated keys (`note["sub-category"]`). An earlier regeneration switched to dot form on a theory; that was reverted because hyphenated keys parse as subtraction in Bases expression contexts and the bracket form was the deliberate, documented choice. Only two bases changed from v2 (all-prompts, by-category, to add the `skill` type via an `or:` block) plus the three new category bases; the other eight are byte-identical to v2.
- setup is modeled as a guided interview (one question at a time, skip/pause allowed) that produces a profile record feeding the durable-knowledge prompts and the install router, rather than asking a beginner to author context documents from scratch.
- copilot-skills are app how-to guides (`type: skill`), not paste-in prompts; they have no fenced prompt block, and the Word renderer skips the prompt block for them.
- Reviewer agents were re-used as fixers, scoped to one category folder each, forbidden from touching manifests, bases, git, or files outside their folder; central greps verified their mechanical output and three high-stakes regulatory fixes were spot-checked directly on disk (the passoff-recurring lesson that fork self-reports can lie).
