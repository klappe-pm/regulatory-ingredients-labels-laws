## Key Decisions

- Register is flat CSV (clean git diffs, opens in any spreadsheet); catalogs and
  schema are JSON. Standard library only, no new dependencies.
- Obligations are tagged by ingredient function, not only by name, so a ban on a
  function resolves to every affected product.
- The 50-state surface starts as aggregate `us-multistate-*` monitoring rows,
  promoted to per-state rows as bills are confirmed.
- Detection flags; humans edit. `scan` hashes source content against a
  last-seen state and only writes the baseline on explicit `--update`.

## Verification

- `make test` passes (doctor, audit-strict, regwatch-validate).
- `scan` verified to report NEW, then UNCHANGED, then CHANGED across snapshot
  edits.

## Risks and Open Questions

- Seed rows are `secondary-digest` confidence: derived from a conference digest,
  not primary legal text. Confirm against source text before any label use.
- Live html fetch hashes whole pages; per-source parsing is needed later to
  reduce noise.
- Per-state coverage for all 50 states is modeled but not yet populated.
- Automation runtime, cadence, and delivery channel (question 5) remain open,
  deferred to Phase D.

## Next Actions

1. Capture source snapshots or wire `--live` per source (Phase B).
2. Confirm secondary-digest rows against primary source text.
3. Promote aggregate multistate rows into per-state obligations (Phase C).
4. Decide runtime, cadence, and delivery channel (Phase D).

## Do Not Do

- Do not treat the register or any digest as legal advice or a compliance fact.
- Do not let `scan` auto-edit the register.
- Do not commit local source snapshots.
