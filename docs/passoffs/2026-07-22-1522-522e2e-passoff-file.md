# 2026-07-22-1522-522e2e-passoff-file

## Summary

Second phase of the prompt-library session (first phase: PR #34, adversarial-review hardening). The specialist found the prompts awkward to navigate and the YAML non-compliant, so the library was redesigned for human use and merged as PR #35. Every prompt file now reads top-down in six sections (prompt-summary, use-cases, expected-outputs, prompt, how-to-run, guardrails), with the paste-into-Copilot fence byte-identical to the hardened version (verified against a pre-edit snapshot, 32 of 32 fences). Frontmatter now complies with the vault linter schema: `types` as a list, key order domain/category/sub-category/types/dates then alphabetical with `aliases` and `tags` last, enforced by a new normalizer script. Every prompt carries 6 to 10 natural-language aliases for quick-switcher search. Navigation was flattened: the 12 per-category index notes and 12 per-category bases were deleted; the home note (Bases tables), a new Dataview prompt-explorer dashboard (starts empty, filters by frontmatter properties and alias search), and the user guide are the only navigation surfaces.

## Key decisions

- The fence is the contract: the restructure was executed by 12 scoped agents forbidden from altering fence bodies, and integrity was verified centrally against a JSON snapshot taken before any edit, not from agent self-reports.
- Frontmatter compliance went to the linter's model (`types` list, aliases/tags last) rather than the old markdown-style order, since `linter.yaml` is the control plane the vault actually runs.
- Per-category indexes and bases were deleted rather than slimmed (user choice: drop category indexes); category browsing is served by the home page's grouped Bases tables and the explorer's category dropdown.
- The Dataview explorer defaults to showing nothing until a property or search term is chosen (user requirement), and degrades gracefully: the guide tells the user the Bases tables work without any plugin.
- Mid-session the concurrency guard flagged a second live session registered on the guard-provisioned worktree; per the user's direction the work moved to a session-owned worktree (`prompts-redesign-a395b4`, branch `claude/prompts-redesign-a395b4`) via a git-apply patch transfer, and all verification re-ran there.
