# 2026-06-24-1130-passoff-file

## Summary

Set up the bi-weekly team report automation and recorded this passoff. A new
scheduled workflow renders the tiered reports, the newsletter, and the records
export every two weeks and uploads them as an artifact. Added a make target to
regenerate the team report set locally.

## Files Changed

- `.github/workflows/regwatch-biweekly.yml` - the bi-weekly report. Fires every
  Monday; a gate job runs the report only on even weeks (a stable 14-day cadence
  anchored to the Unix epoch), and `workflow_dispatch` always runs. Validates,
  scans live, ingests the Federal Register, renders v1/v2/v3 over the last 14
  days, regenerates the newsletter and the export, includes the one-pager, and
  uploads everything as the `regwatch-biweekly` artifact.
- `Makefile` - `regwatch-rollout` target regenerates the committed v1/v2/v3
  reports, newsletter, and export in one command.
- `regwatch/regwatch-README.md`, `docs/reference/regwatch-troubleshooting.md` -
  document the bi-weekly workflow and the new target.

## Key Decisions

- GitHub cron cannot express "every two weeks", so the workflow fires weekly and
  a gate job skips odd weeks. The cadence is date-based (epoch week parity), so a
  missed run does not shift it, and manual dispatch bypasses the gate.
- The bi-weekly report window is 14 days (`briefing --since-days 14`), with
  ingest looking back 21 days for candidate completeness.
- Delivery remains an artifact for now; an email or Drive transport is the open
  next step, pending the team's cadence and channel decision.
