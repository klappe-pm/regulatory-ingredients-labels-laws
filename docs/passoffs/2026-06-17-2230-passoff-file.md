# 2026-06-17-2230-passoff-file

## Summary

Wired the live FDA Federal Register feed. The `ingest` command pulls recent FDA
documents from the Federal Register API, filters to beverage-relevant ones by
CFR part and keyword, and writes candidate change-log events flagged
`unconfirmed` with the CFR references the API itself reports. The briefing
surfaces candidates in a dedicated section; a human confirms before promotion.
The daily and weekly loops now run `ingest --live` before rendering.

## Files Changed

- `scripts/regwatch_ingest.py` - Federal Register query builder, relevance
  filter, and candidate parser (CFR sourced from the API).
- `scripts/regwatch.py` - `ingest` command; briefing now loads and passes
  candidates.
- `scripts/regwatch_briefing.py` - "Newly Detected — Unconfirmed" section.
- `.github/workflows/regwatch.yml`, `.github/workflows/regwatch-daily.yml` -
  run `ingest --live` and publish candidates/briefing.
- `Makefile` - `ingest` added to the smoke run.
- `.gitignore` - ignore generated `regwatch-ingest-candidates.json`.
- `regwatch/regwatch-README.md`, `docs/plans/deliverable-3-regulatory-monitoring-design.md`
  - documentation.

## Key Decisions

- Human-in-the-loop preserved: ingestion writes `unconfirmed` candidates to
  state; it never edits the curated change log or register. Promotion is manual.
- CFR tagging comes from the API's `cfr_references`, so it is sourced, not
  guessed.
- Offline degrades to zero candidates; `--from-file` parses a saved response for
  deterministic testing.

## Verification

- `make test` passes (now runs `ingest` in the smoke target).
- `ingest --from-file` parsed a Federal Register fixture: kept the two food
  rules with CFR (21 CFR 74/81, 101), dropped an unrelated compounding notice;
  the briefing rendered the candidate section.
- Live fetch from this sandbox returns HTTP 403 (network policy blocks outbound
  to the Federal Register); the public API is reachable from the Actions runner,
  where the loops will populate candidates.

## Risks and Open Questions

- This sandbox cannot reach the live API; verify the live path in the Actions
  runner on the first scheduled or dispatched run.
- Candidate promotion into the curated change log is manual by design; consider
  a lightweight `--promote` review flow later.
- The relevance filter is keyword and CFR-part based; tune as false positives or
  misses appear.

## Next Actions

1. Confirm the live path on the first workflow_dispatch of regwatch-weekly.
2. Optionally add a guided promotion flow from candidates to the change log.
3. Add the FDA warning-letter database as a second live feed when feasible.

## Do Not Do

- Do not promote unconfirmed candidates into the change log automatically.
- Do not treat candidates or CFR tags as legal advice.
